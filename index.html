01 / THE THROUGHLINE

One security theme.
Three layers of work.

The frontend, CI, and release work form a connected effort: remove vulnerable foundations, make dependency remediation deliverable, and hold the resulting artifacts to an explicit security standard.

03 RELEASES

Qualify what
users receive.

Release tooling connects source, wheels, container images, scans, and publication. The default gate is zero fixable vulnerabilities, with explicit, reviewed exceptions bound to exact release artifacts.

Qualified releases with kfpr ↗Retain findings & gate release images ↗Exact-release security approvals ↗

THE STANDARD

Zero fixable vulnerabilities by default. This is a release qualification policy, not a claim that every release contains zero known findings. The 2.18.0 release notes document accepted findings in selected dependencies and upstream images. Earlier, 2.17.3 reported zero scanner-reported fixable image findings across 24 image/platform combinations, while Python 3.9 dependencies retained documented exceptions.

05 / NOTES & SOURCES

A portfolio with a paper trail.

Scope

All 468 authored PRs in kubeflow/pipelines, created January 9–November 2, 2026. Counts include merged, open, and closed PRs. Backports and follow-ups count separately. Review work in other authors’ PRs is outside this dataset.

Classification

One editorial purpose per PR, based on titles, descriptions, and file paths. Security/dependency maintenance includes ordinary upgrades. Component breadth is measured separately from purpose, using complete changed-file lists. Volume is not an effort or impact score.

Advisory evidence

Public disclosure counts use publisher identity, CVE fields, patched versions, and linked PRs. This site uses public evidence only. Private advisory activity, including aggregate counts, is excluded; the full private triage workload is not quantified here.
